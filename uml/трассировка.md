## Классы и информационная модель

Диаграмма классов развивает информационную модель IDEF1 работы № 2. Соответствие сущностей и классов приведено ниже.

Колонки: (0.8fr, 0.8fr, 1.4fr)
Подпись: Соответствие сущностей IDEF1 и классов UML

| Сущность IDEF1 | Класс UML | Примечание |
| --- | --- | --- |
| ADMIN | Administrator | Наследник User, получает право публикации |
| TEACHER | Teacher | Наследник User |
| TEACHER_AVAILABILITY | Teacher.availability | Доступность хранится как набор слотов |
| STUDENT | — | Студент смотрит публичное расписание без входа, класса нет |
| STUDY_GROUP | StudentGroup | — |
| DISCIPLINE | TeachingAssignment.courseName | Отдельный класс не вводится |
| LESSON, LESSON_GROUP | TeachingAssignment | Учебное назначение: дисциплина, преподаватель, группы, часы. Кратность 1..* у групп сохраняет потоковые занятия |
| BUILDING | Classroom.buildingName, buildingAddress | Корпус нужен для справочных сведений (ПТ-08) |
| ROOM | Classroom | — |
| TIME_SLOT | TimeSlot | — |
| SCHEDULE | ScheduleVersion | Статус и дата публикации совпадают по смыслу |
| SCHEDULE_ENTRY | Lesson | Занятие в конкретной версии: слот и аудитория |
| SCHEDULING_CONSTRAINT | параметры generateDraft(), правила ConstraintChecker | Веса критериев передаются в params |
| CHANGE_REQUEST | — | Заявки преподавателя в этом комплекте не моделируются |

## Согласованность

Подпись: Результаты проверки согласованности модели

| Контроль | Результат |
| --- | --- |
| Имена актёров | Администратор, Преподаватель и Студент совпадают с внешними сущностями DFD и IDEF0 работы № 2 и одинаковы на диаграммах прецедентов, последовательности и деятельности. Внешняя учебная ИС одинакова на диаграммах прецедентов, компонентов и развёртывания |
| Имена классов | Линии жизни трёх диаграмм последовательности и дорожки диаграммы деятельности — экземпляры классов ScheduleUI, ScheduleService, ConstraintChecker, ScheduleVersion, TeachingAssignment, Lesson, Teacher, Classroom и Administrator |
| Операции | Каждая операция диаграммы классов вызывается хотя бы на одной диаграмме последовательности. Сообщения подписаны теми же именами и параметрами |
| Статусы | Черновик, Генерация, Проверка, Готово, Опубликовано, Архив, Ошибка и Отменено одинаковы на диаграмме состояний, в сообщениях setStatus() и в спецификациях прецедентов |
| Прецеденты и потоки | UC-03 раскрыт последовательностью 1 и деятельностью, UC-06 — последовательностью 2, UC-08 — последовательностью 3 и деятельностью |
| Ограничения | Пересечения, вместимость и доступность — жёсткие ограничения. Окна — мягкий критерий в функции F. Оптимизация жёсткие ограничения не нарушает |
| Архитектура | Компоненты и артефакты развёртывания названы одинаково. В квадратных скобках компонентов указаны классы, которые компонент реализует |
| Открытые вопросы | Обработка заявок преподавателя (DFD 5.0, CHANGE_REQUEST) сведена к переносу занятия администратором. Требования ПТ-10, ПТ-11, СХ-05, СХ-06 и О-07 введены в этой работе и ждут подтверждения владельца продукта |

## Проверочные сценарии

Колонки: (14mm, 1fr, 1fr)
Подпись: Проверочные сценарии и ожидаемый результат

| Тест | Входная ситуация | Ожидаемый результат |
| --- | --- | --- |
| T-01 | Два занятия одного преподавателя поставлены в один слот | Второе занятие не назначается, конфликт показан (КП-01) |
| T-02 | Аудитория меньше численности группы | Вариант размещения отклоняется (КП-02) |
| T-03 | Слот закрыт по доступности преподавателя | Занятие в слот не ставится (КП-02) |
| T-04 | Слотов не хватает для полной нагрузки | Статус «Ошибка» и список непокрытых часов (КП-03) |
| T-05 | Занятие переносится в занятый слот | Отказ, исходный вариант не меняется (КП-04) |
| T-06 | Публикуется версия с конфликтом | Публикация запрещена, прежняя версия доступна (КП-05) |
| T-07 | Есть несколько допустимых вариантов | При заданных весах выбранный вариант не хуже базового по F (КП-06) |
| T-08 | Студент открывает расписание, пока новая версия в статусе «Готово» | Показана прежняя опубликованная версия (КП-05, КП-07) |
