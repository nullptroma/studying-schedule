# Реестр требований

Коды сгруппированы по разделам спецификации: БТ — бизнес-требования, ПТ — пользовательские, СХ — системные характеристики, АК — атрибуты качества, О — ограничения. Колонка «Источник» связывает код с карточкой требования работы № 1 или с моделью работы № 2. Пометка «работа 4» означает требование, введённое при UML-моделировании: в ранних работах его не было.

## Критерии приёмки

По критериям приёмки проверяется модель и будущая реализация. Ссылки на них стоят в спецификациях прецедентов и в проверочных сценариях.

Колонки: (16mm, 1fr)
Подпись: Критерии приёмки

| Код | Проверка |
| --- | --- |
| КП-01 | В опубликованной версии нет пересечений по преподавателю, группе и аудитории |
| КП-02 | Для каждого занятия соблюдены вместимость и тип аудитории и доступность преподавателя |
| КП-03 | Число размещённых часов равно обязательному фонду по каждому учебному назначению |
| КП-04 | Недопустимый перенос отвергается, предыдущий корректный вариант сохраняется |
| КП-05 | Невалидная версия не публикуется, ранее опубликованное расписание остаётся доступным |
| КП-06 | При одинаковых весах оптимизация не ухудшает значение F относительно базовой версии |
| КП-07 | Студент и преподаватель видят только опубликованные сведения в пределах своих прав |
